# ADR-16 — Remotion como motor de motion graphics: avaliado, não adotado por ora

**Data:** 2026-11-09 · **Estado:** avaliado; decisão **não adotar como dependência do plugin**, revisitar sob condições abaixo · **Prova:** [`2026-11-09-remotion-poc/`](2026-11-09-remotion-poc/README.md)

## Contexto

[Remotion](https://www.remotion.dev/) faz vídeo por código com React: cada quadro é uma página HTML/CSS renderizada
num Chrome headless e costurada pelo ffmpeg embutido. Em 2026 ganhou o que o mercado chama de "agentic video":
*Agent Skills* oficiais para Claude Code, Codex e Cursor (`npx skills add remotion-dev/skills`), `@remotion/effects`
(~80 efeitos, versão WebGPU de cada um), ~20 transições, `@remotion/captions` (SRT/VTT → legenda estilo TikTok),
Studio com linha do tempo e keyframes, Player para embutir e Lambda para render em lote. Versão avaliada: **4.0.542**
(09/11/2026), Chrome Headless Shell 158, Node 24.

A pergunta: ele melhora o que o plugin já faz com Manim (`/video-animado`, `/animacao`), ASS/libass (`/lettering`,
`/legenda`, `/checklist`) e `xfade` do ffmpeg? E cabe nas promessas do plugin (ADR-01, 05): open source, local,
determinístico, sem SaaS?

## O que foi medido

Projeto mínimo (título com `spring`, transição `wipe`, lower third, legenda por palavra com destaque, a partir dos
tempos reais da narração do curso de bateria) e uma composição que queima legenda sobre 60 s de filmagem.
Máquina: Intel 8 threads, sem GPU, concorrência padrão (4 processos).

| Caso | Remotion | Hoje no plugin |
|---|---|---|
| Cena gerada 1080p30, 33,6 s | 49–67 s (~17 quadros/s), **md5 idêntico** em dois renders | Manim: ~30 s a 1 min por cena de 10–15 s (`/video-animado`), também determinístico |
| Legenda por palavra sobre 60 s de filmagem | **318 s** (`OffthreadVideo` decodifica, o Chrome compõe, o ffmpeg recodifica) | `ffmpeg -vf subtitles=`: **17,6 s** |
| Instalação | Node + 518 MB de `node_modules` + Chrome Headless Shell (download do remotion.media) | uv + Manim/ffmpeg já exigidos |
| Tipografia e layout | CSS completo (flex, quebra, fontes do sistema via fontconfig), sem esforço | ASS: posição e tamanho; Manim: `Text` com Pango, layout à mão |

Pegadinha real encontrada: `createTikTokStyleCaptions()` separa palavras pelo **espaço inicial** de cada `Caption`;
`parseSrt()` de um SRT por palavra não traz esse espaço e tudo vira uma página só. Está anotada na prova.

## Licença (o ponto decisivo)

Remotion é **source-available, não open source** (a própria FAQ diz que não atende a definição da OSI). Licença
gratuita só para pessoa física, organização com **até 3 pessoas**, sem fins lucrativos e avaliação. Com 4 ou mais
pessoas, **Company License**: US$ 25/mês por pessoa que escreve código Remotion, **inclusive via agente de IA**
("Remotion for Creators"), ou US$ 0,01 por render com mínimo de US$ 100/mês ("Automators"); Enterprise a partir de
US$ 500/mês. A chave de licença liga telemetria (IP, domínio, tipo de render). Quem só recebe o mp4 não precisa de
nada; quem **roda ou edita** o projeto Remotion precisa da própria licença, com headcount somado entre as partes.
Código exportado precisa declarar que foi feito com Remotion. O preset `cube()` das transições é pago à parte.

Para o plugin isso significa: toda skill que mandasse o Claude escrever uma composição Remotion tornaria **cada
usuário corporativo** (4+ pessoas na empresa) um "Creator" sujeito a assento pago, e o README não poderia mais dizer
"open source, local, sem SaaS" sem ressalva. O uso em empresa (o caso de quem mantém o plugin) já exigiria licença.

## Decisão

1. **Não adotar** o Remotion como dependência, motor alternativo ou skill do plugin nesta fase. Manim (MIT), ffmpeg
   (LGPL/GPL), libass e Verovio continuam a base; o critério de licença do ADR-05 (open source de verdade) prevalece
   sobre a conveniência de layout.
2. **Nunca** usar Remotion para passes sobre filmagem (legenda, lettering, tela dividida): 18× mais lento que o filtro
   do ffmpeg, sem ganho de qualidade. Se um dia entrar, é só para **gráficos gerados** (cartões, intros, cenas de
   texto), renderizados com alpha (ProRes 4444/WebM) e compostos pelo ffmpeg, para a filmagem nunca passar pelo Chrome.
3. O que a avaliação ensina e **entra no plugin sem o Remotion** (melhorias derivadas, para versões futuras):
   - **legenda por página com palavra destacada** no `/legenda` estilo reels: a paginação por janela de tempo
     (1,2–1,5 s) com a palavra atual em cor é reproduzível em ASS com tags `\k`/`\t` a partir do `.words.srt`;
   - **spec declarativa por JSON** como a do Remotion (`inputProps`): já é o que `cenas/<slug>.json`, `textos.json`
     e `padroes.json` fazem; manter esse padrão em toda skill nova;
   - **folha de contato como "Studio"**: a revisão por quadros (`folha_cenas.py`, `/prova`) cumpre o papel do preview
     interativo; não há o que copiar além de manter o hábito.
4. **Revisitar** se **(a)** a licença mudar (há mudança anunciada para a 5.0, sem detalhe público) ou o usuário/
   organização já tiver assentos, **e (b)** um projeto pedir layout de texto que ASS e Manim não entregam (cartões com
   muitas linhas, listas com quebra automática, tipografia cinética densa). Nesse cenário a forma é uma skill opcional
   `/remotion` com `doctor.sh` avisando a licença, `npx skills add remotion-dev/skills` no projeto e render só com alpha.

## Consequências

- Nenhum código do plugin muda; a prova fica em `docs/adr/2026-11-09-remotion-poc/` (fora do CI) para repetir a medição.
- O plugin segue 100% open source e sem telemetria de terceiros, como o README promete.
- Fica registrado o custo de oportunidade: layout de texto em CSS é claramente mais produtivo que ASS; a resposta do
  plugin a isso é melhorar o `lettering_ass.py` (estilos `cartao`/`capa` já existem) e a paginação do `/legenda`,
  não trocar de motor.
